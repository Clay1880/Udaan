# Udaan: Air Force Day Event Website, Design Spec

Date: 2026-10-06

## 1. Purpose
A website for "Udaan", a college Air Force Day event, with two competitions:
1. **Quiz** on the Indian Air Force, with questions generated by Gemini.
2. **Poster making**, where students upload a PDF, JPG or PNG.

Success criteria:
- Students (mostly on phones) can sign in, register, take the quiz once, and submit/replace a poster, all within the event window.
- Organisers can see and export all results and posters.
- The site looks intentional and designed, not like a generic template.

## 2. Decisions

| Topic | Decision |
|---|---|
| Eligibility | Any Gmail account. Open to FE, SE, TE, BE. |
| Branches | Comp, IT, ENTC, Mech, ARE (Automation & Robotics) |
| Poster | Open to all years |
| Quiz | 1 attempt, 20 MCQs, 15 minutes, resumes on reload |
| Window | 8 Oct to 9 Oct 2026 (IST), 00:00 on the 8th to 23:59 on the 9th. Quiz and poster submissions are closed outside it. The site stays visible. |
| Poster replace | Allowed any time inside the window |
| Admin | Fixed allowlist of Gmail addresses (config). View and export only. |
| Stack | Next.js + Firebase (Auth, Firestore, Storage). Blaze plan. |
| Look | Cockpit / air-force-operations. Mobile-first, good on laptop. |

## 3. Pages
- `/` Landing: title, intro, Quiz and Poster cards, Google sign-in.
- `/register` One-time profile: name, roll number, year, branch. Required before competitions.
- `/dashboard` Status of both competitions.
- `/quiz` Intro, then one question at a time with timer, navigator and submit. Shows score after.
- `/poster` Drag/tap upload, type and size validation (max ~10 MB), preview, replace.
- `/admin` Allowlisted only. Tabs: Participants, Quiz results, Posters. Filters by year and branch. CSV export. Bulk poster download.

Outside the window, `/quiz` and `/poster` show a locked state with the open and close dates.

## 4. Quiz mechanics
- **Start** (server route): requires auth, completed profile, inside the window, and no existing attempt. Calls Gemini for 20 MCQs on the Indian Air Force (history, aircraft, ranks, operations, technology). Output is validated against a strict JSON schema, then stored with `startedAt` in Firestore.
- **Hidden answers:** the client receives questions and options only. Correct answers stay server-side.
- **Resume:** reload returns the same questions and saved answers. Deadline is `startedAt + 15 min` on the server clock. The timer continues; it never restarts.
- **Save:** each answer is saved on selection (retried on network failure).
- **Submit or timeout:** the server scores. Submissions after the deadline (small grace for latency) are rejected and the attempt is scored from saved answers. A second attempt is blocked.
- **Window close:** an attempt started before close may be finished within its own 15 minutes. No new attempts after close.
- **Gemini failure:** retry, then fall back to a pre-written bank of at least 30 questions, so the quiz always starts. The Gemini key lives only on the server.

## 5. Data model (Firestore and Storage)
- `users/{uid}`: name, rollNo, year, branch, email, createdAt.
- `attempts/{uid}`: questions, correctAnswers (server-only), answers, startedAt, status, score.
- `posters/{uid}`: storagePath, fileType, uploadedAt, replacedAt.
- Storage: `posters/{uid}/<file>`; replacing overwrites.
- **Rules:** Firestore is closed to clients entirely; all data access goes through server routes (Admin SDK) that verify the user and, for admin routes, the allowlist. Storage lets a student only *create* a size/type-limited file under their own `posters/{uid}/` folder (no read, overwrite or delete). The event window is enforced server-side when a poster upload is confirmed and for every quiz call; a poster only counts once confirmed.

## 6. Look and feel
Reference: `poster.jpeg` (the NSS event poster). The site recreates its style in CSS/SVG with an air-force twist.
- **Surface:** cream paper with subtle grain; content sits on blue gridded panels like the poster's blue square.
- **Type:** chunky outlined bubble lettering (Chango) in yellow and red for headings, with a hard offset shadow; a rounded friendly face (Fredoka) for body text.
- **Components:** "sticker" cards, tags and buttons with a thick dark outline, hard offset shadow and slight tilt; pink, green and yellow accents; sparkles; a `QUIZ!` starburst.
- **Air-force twist:** a cartoon yellow jet replaces the pointing hand, clouds replace the pink circles, a dotted contrail, a tricolour badge, and stamps like "Mission complete".
- **Branding:** NSS logo in the header (placeholder until the file is supplied); footer reads "NSS · 2026 · On the occasion of Air Force Day".
- **Timer:** a sticker that is green, yellow under 3:00, red (pulsing) under 1:00.
- **Phone first:** one column, answer buttons at least 48px tall, sticky timer, bottom Prev/Next bar.
- **Laptop:** side question navigator in the quiz, full-width layout elsewhere.
- **Admin:** same colours and outlines, kept plain and readable for tables.
- **Motion:** limited to page-load fades and the timer pulse; respects reduced-motion.

## 7. Errors and testing
- Clear messages for wrong file type, oversize file, lost connection, locked window, and non-admin access.
- Unit tests: scoring, timer and resume logic, window checks, allowlist check.
- Firebase emulator tests for security rules.
- Manual browser walkthrough at phone and laptop sizes.

## 8. Open items
- Admin email addresses to be supplied (stored in config).
- Final event timezone assumed to be IST.
- Poster file size limit assumed at 10 MB.
